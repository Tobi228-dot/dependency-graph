# Dependency Graph

Практическая работа по дисциплине «Конфигурационное управление».
ИКБО-32-25, вариант **13**. Язык реализации — Python.

Цель работы — инструмент визуализации зависимостей npm-пакетов.
Реализован **этап 1: минимальный прототип с конфигурацией**.
Программа читает INI, проверяет все параметры и выводит их как `ключ=значение`.
Получение зависимостей, обход графа и создание SVG относятся к следующим
этапам и пока не выполняются. Готовые средства получения зависимостей
не используются; внешних Python-зависимостей нет.

## Запуск и проверка

Нужен Python 3.10 или новее. Сборка и установка пакетов не требуются.
Команды выполняются из корня репозитория:

```sh
sh run.sh --config examples/config.ini
sh run.sh --config examples/test.ini
python3 -m unittest discover -s tests -v
```

На Windows и других системах можно запускать напрямую:

```sh
python src/main.py --config examples/config.ini
python -m unittest discover -s tests -v
```

Справка: `python3 src/main.py --help`.
Единственная опция CLI — обязательная `--config`, путь к INI-файлу.
Все настройки предметной области берутся из этого файла.

## Настройки

Файл в UTF-8 должен содержать единственную секцию `[app]`.
Все пять ключей обязательны; пустые, повторные и неизвестные ключи запрещены.
Секция `DEFAULT` не используется и отклоняется.

| Ключ | Назначение и допустимые значения |
| --- | --- |
| `package` | Имя npm-пакета: `express`, `@types/node`. В тестовом режиме — заглавные латинские буквы, например `A`. |
| `repository` | HTTP(S) URL без пароля, query и fragment; в тестовом режиме — путь к существующему читаемому файлу. |
| `test_mode` | Логическое значение: `true/false`, `yes/no`, `on/off`, `1/0`, без учёта регистра. |
| `version` | Конкретная SemVer-версия: `4.18.2`, `1.0.0-beta.1`; диапазоны и `latest` запрещены. |
| `output` | Имя будущего SVG, например `graph.svg`; родительский каталог должен существовать. |

Относительные пути `repository` и `output` отсчитываются от каталога INI.
Проверка URL синтаксическая: на первом этапе сеть не используется.
Тестовый файл проверяется на доступность, его содержимое пока не разбирается.
Выходной файл не создаётся и не перезаписывается. Расширение SVG выбрано
согласно требованиям пятого этапа варианта 13.

Пример `examples/config.ini`:

```ini
[app]
package = express
repository = https://registry.npmjs.org
test_mode = false
version = 4.18.2
output = graph.svg
```

Ожидаемый вывод:

```text
package=express
repository=https://registry.npmjs.org
test_mode=false
version=4.18.2
output=graph.svg
```

Для тестового режима приведены `examples/test.ini` и `examples/repository.json`.

## Демонстрация ошибок

Скопируйте пример INI и поочерёдно подставьте значения из таблицы.
Запустите программу с `--config`, указывающим на изменённый файл.
Она завершится с кодом **2** и сообщением в stderr, без traceback.
Успешное выполнение возвращает **0**.

| Параметр | Ошибочное значение | Причина |
| --- | --- | --- |
| `package` | `Bad Name` | Некорректное имя пакета |
| `repository` | `ftp://example.org` | Неподдерживаемая схема URL |
| `repository`, тестовый режим | `missing.json` | Несуществующий файл |
| `test_mode` | `maybe` | Не логическое значение |
| `version` | `latest` | Нужна конкретная версия SemVer |
| `output` | `graph.png` | Требуется расширение SVG |

Например, при `test_mode = maybe`:

```text
Ошибка конфигурации: test_mode: нужно true/false, yes/no, on/off, 1/0
```

Автотесты воспроизводят ошибки всех пяти параметров, пропущенные и пустые
значения, неправильный INI, кодировку, недоступные пути и проверяют CLI.

## Структура и функции

- `src/main.py` — приложение и валидация.
- `tests/test_cli.py` — тесты на стандартном `unittest`.
- `examples/` — обычная и тестовая конфигурации, тестовый источник.
- `run.sh` — запуск из любого рабочего каталога.

| Функция / класс | Назначение |
| --- | --- |
| `Settings` | Неизменяемый набор пяти проверенных параметров |
| `ConfigError` | Ошибка конфигурации, обрабатываемая CLI |
| `read_section(path)` | Чтение INI, проверка секций, ключей и пустых значений |
| `validate_package(package, test_mode)` | Проверка имени пакета |
| `validate_version(version)` | Проверка SemVer, включая prerelease |
| `local_path(value, base)` | Разрешение пути относительно INI |
| `validate_repository(repository, test_mode, base)` | Проверка URL или тестового файла |
| `validate_output(output, base)` | Проверка имени SVG и родительского каталога |
| `load_settings(path)` | Чтение и полная проверка настроек |
| `main(argv=None)` | Разбор CLI, вывод параметров и обработка ошибок |

Этапы сохраняются отдельными коммитами в формате Conventional Commits.
